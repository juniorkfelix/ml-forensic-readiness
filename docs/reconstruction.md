# Reconstruction Engine

**Status:** implemented in Phase 14 (`src/mlfref/reconstruction/`). Neutral event vocabulary: see `timeline.py` (D-045).

## 1. Fairness contract (§45, §46)

- There is **one** entry point, `reconstruct(evidence_dir, incident_ticket) -> Reconstruction`, and
  the same logic runs for A, B and C. There are no per-pipeline reconstruction functions and no
  branching on `pipeline_mode`.
- The engine discovers which evidence **sources** are present (application log, artefact listing,
  MLflow reference, forensic store) through source adapters. Each adapter turns its source into a
  common set of **observations**: `(kind, artefact refs, time, attributes, source, basis)`. With
  less evidence there are simply fewer observations.
- Correlation, timeline construction and root-cause analysis operate only on observations.
- The engine never invents events. A step with no supporting observation is reported as
  `UNKNOWN`, `NOT_OBSERVABLE` or `INSUFFICIENT_EVIDENCE`, with the reason.
- The engine never reads ground truth, never parses experiment IDs, and never uses external
  reference data (D-017).

## 2. Backward trace

```
incident ticket (request_id, time, input, observed prediction)
  → INFERENCE    which request record matches? which deployment/model served it?
  → DEPLOYMENT   which model artefact was deployed, and when?
  → MODEL        which artefact (hash/path/registry version)? generated by which run?
  → TRAINING RUN which run, when, with which hyper-parameters and dataset?
  → DATASET      which dataset state was used (ID/digest/profile/manifest)?
  → PRIOR STATE  was a different earlier state registered? what changed between them?
```

At each hop the engine records the **evidence basis**: the observations that support the link
(e.g. "model SHA-256 in INFERENCE_RESULT equals MODEL_HASHED artefact_hash"). It also assigns a
confidence class:

| Class | Meaning |
|---|---|
| `STRONG` | a cryptographic hash or explicit ID link recorded at the time of the event |
| `MODERATE` | a recorded ID/path link without a hash, or native MLflow lineage |
| `WEAK` | inferred from file paths, time proximity or file-system mtimes |
| `NONE` | no supporting evidence, so the link is `UNKNOWN` |

## 3. Root-cause analysis

Only from evidence:
- **Dataset state change:** a registered dataset differs from the dataset used for training
  (digest/hash mismatch) → dataset changed between registration and training. Timing is bounded by
  the two observations (`time_basis = bounded`).
- **Nature of change** (needs two per-sample manifests, i.e. only when both were preserved): the
  set of changed sample IDs; whether labels only or pixels + labels changed; label transition matrix
  (e.g. class 1 → 9).
- **Profile-level signal** (from MLflow dataset profiles): per-class count differences, which
  indicate label changes without identifying individual samples.
- Findings are expressed as observations ("250 samples changed label 1→9, pixels unchanged"), not
  attack names. The engine may map them to a hypothesis category (`LABEL_MODIFICATION`,
  `CONTENT_AND_LABEL_MODIFICATION`) using a fixed rule written before any results existed.

## 4. Output

`results/reconstruction/<EXP-ID>.json` and `.md`. The harness names the files. Inside, the run is
referred to as `RUN-<uuid>`.

Contents: incident, evidence sources available/missing, observations used, reconstructed events
(type, time, `time_basis` ∈ {exact, bounded, inferred, unknown}, artefact refs, evidence basis,
confidence), chronology, artefact relationship graph (PROV-style: `USED`, `WAS_GENERATED_BY`,
`WAS_DERIVED_FROM`), integrity findings, identified model / training run / dataset / prior dataset,
changed-sample set (if derivable), root-cause finding, missing evidence, limitations, runtime.

## 5. Scoring interface (for the evaluator)

Every reconstructed event carries a normalised `event_class` from the vocabulary in
`config/evaluation_schema.yaml` and artefact references (path, ID or hash). The evaluator maps these
to GT through canonical content hashes (D-020). The engine does not see this mapping.
